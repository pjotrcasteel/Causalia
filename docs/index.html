The production bugs unit tests rarely see

Concurrency failures stop being ghost stories.

Causalia controls scheduling and time, injects the difficult outcome, and keeps the exact sequence when an invariant breaks. You get a failure you can reproduce instead of a log you can only speculate about.

Five-minute start

Start with your existing solution.

The CLI finds simulation-friendly boundaries without rewriting your production code.

Read the full getting started guide →
terminal
# Install the adoption CLI
$ dotnet tool install --global Causalia.Tool --version 2.1.1

# Inspect without changing your solution
$ dotnet causalia inspect MyService.slnx

✓ 7 candidate boundaries found
✓ TimeProvider seam detected
! 2 uncontrolled scheduling calls

# Generate the first deterministic test
$ dotnet causalia init MyService.slnx
